# RUN: llvm-mc --disassemble -triple=alpha-unknown-linux-gnu %s 2>&1 | FileCheck %s

# A floating-point operate carries its trap and rounding qualifiers in the
# function field, and only the unqualified encodings have a decoder table
# entry, so the qualifier is taken out of the word and the rest decoded.  What
# comes back has to be a combination the instruction actually defines.

# CHECK-DAG: addt/su $f1, $f1, $f2
0x02 0xb4 0x21 0x58

# cvtst's own function field carries 0x200 in the trap-mode position -- that is
# what distinguishes it from cvtts, not a qualifier -- so it decodes with no
# qualifier at all rather than one nothing can spell.
# CHECK-DAG: cvtst $f0, $f1
0x81 0x55 0xe0 0x5b

# The same word with an underflow bit merged in is not an instruction: GNU
# objdump prints it as .long.  Taking the trap bits out leaves cvtts's own
# encoding, so accepting it would name a real conversion running the other way.
# CHECK-DAG: warning: invalid instruction encoding
0x81 0x75 0xe0 0x5b
